# Feature dictionary

Team: Minh Nguyen, Krish Iyer, Calvin Zheng

One row per engineered feature in `data/features/features.parquet`. Someone who has never seen your code should understand each feature from this page alone.

| Feature | Source table | Meaning | How it was built |
|---|---|---|---|
| BUREAU_COUNT | bureau | Number of credits the applicant has with other lenders, whether open or closed. | Counts `SK_ID_BUREAU` records per applicant using `aggregate_bureau`. Applicants with no bureau records receive 0 through `join_features`. |
| BUREAU_AMT_CREDIT_SUM_MEAN | bureau | Average total credit amount reported by other lenders. | Calculates the mean of `AMT_CREDIT_SUM` per applicant. Missing amounts are ignored. Applicants with no records receive a missing value. |
| BUREAU_AMT_CREDIT_SUM_MAX | bureau | Largest total credit amount reported by another lender. | Calculates the maximum `AMT_CREDIT_SUM` per applicant. Missing amounts are ignored. Applicants with no records receive a missing value. |
| BUREAU_AMT_DEBT_MEAN | bureau | Average amount the applicant still owes other lenders. | Calculates the mean of `AMT_CREDIT_SUM_DEBT` per applicant, ignoring missing values. Applicants with no records receive a missing value. |
| BUREAU_AMT_OVERDUE_SUM | bureau | Total amount currently overdue across the applicant's external credits. | Sums `AMT_CREDIT_SUM_OVERDUE` per applicant. Pandas ignores missing values when summing and returns 0 for an all-missing group. Applicants with no bureau records receive a missing value after joining. |
| BUREAU_DAYS_OVERDUE_MAX | bureau | Greatest reported number of days a credit is currently overdue. | Takes the maximum `CREDIT_DAY_OVERDUE` per applicant, ignoring missing values. Applicants with no records receive a missing value. |
| BUREAU_DAYS_CREDIT_MAX | bureau | How recently the applicant opened a credit reported by another lender. | Takes the maximum `DAYS_CREDIT` per applicant. Since values are generally negative, the value closest to zero represents the most recent credit. Applicants with no records receive a missing value. |
| BUREAU_ACTIVE_COUNT | bureau | Number of external credits that are still active. | Counts rows where `CREDIT_ACTIVE` equals `"Active"` per applicant using `count_where`. Applicants with no bureau records receive 0. |
| BUREAU_CLOSED_COUNT | bureau | Number of external credits reported as closed. | Counts rows where `CREDIT_ACTIVE` equals `"Closed"` per applicant using `count_where`. Applicants with no bureau records receive 0. |
| PREV_COUNT | previous_application | Number of earlier applications submitted to Home Credit. | Counts `SK_ID_PREV` records per applicant using `aggregate_previous`. Applicants with no previous applications receive 0 after joining. |
| PREV_APPROVED_RATE | previous_application | Proportion of earlier applications that were approved. | Uses `share_where` to calculate the share of records with `NAME_CONTRACT_STATUS` equal to `"Approved"`. The rate ranges from 0 to 1. Applicants with no records receive 0 after joining. |
| PREV_REFUSED_RATE | previous_application | Proportion of earlier applications that were refused. | Uses `share_where` to calculate the share of records with `NAME_CONTRACT_STATUS` equal to `"Refused"`. The rate ranges from 0 to 1. Applicants with no records receive 0 after joining. |
| PREV_AMT_APPLICATION_MEAN | previous_application | Average amount requested in earlier applications. | Calculates the mean of `AMT_APPLICATION` per applicant. Missing amounts are ignored. Applicants with no records receive a missing value. |
| PREV_AMT_CREDIT_MEAN | previous_application | Average credit amount Home Credit offered in earlier applications. | Calculates the mean of `AMT_CREDIT` per applicant. Missing amounts are ignored. Applicants with no records receive a missing value. |
| PREV_DAYS_DECISION_MAX | previous_application | How recently Home Credit made a decision on an earlier application. | Takes the maximum `DAYS_DECISION` per applicant. The largest value, generally closest to zero, represents the most recent decision. Applicants with no records receive a missing value. |
| PREV_DAYS_TERMINATION_MEAN | previous_application | Average recorded loan-termination time relative to the current application. | Replaces the `SENTINEL` value in `PREVIOUS_DAY_COLUMNS` with missing values, then calculates the mean of `DAYS_TERMINATION` per applicant. Missing dates are excluded. Applicants with no records receive a missing value. |
| PREV_LAST_STATUS | previous_application | Status of the applicant's most recent previous application. | Sorts by `DAYS_DECISION`, then `SK_ID_PREV`, and keeps the last row per applicant. The largest decision day wins; the largest previous-application ID breaks ties. Applicants with no records receive a missing value. |
| BB_CREDIT_COUNT | bureau_balance | Number of external credit accounts with monthly status history. | Groups monthly records by `SK_ID_BUREAU`, merges with `bureau` to obtain applicant IDs, then counts credits per applicant. Credits without monthly history are excluded. Applicants with no matching history receive 0 after joining. |
| BB_MONTHS_COUNT | bureau_balance | Total monthly status records across the applicant's external credits. | Counts monthly records per credit and sums those counts per applicant. Credits without monthly history are excluded. Applicants with no matching history receive 0 after joining. |
| BB_LATE_MONTHS_COUNT | bureau_balance | Number of monthly records showing a late payment status. | Counts statuses `"1"` through `"5"` per credit, then sums the counts per applicant. Statuses `"C"` and `"X"` are not considered late. Applicants with no matching history receive 0 after joining. |
| BB_LATE_SHARE | bureau_balance | Proportion of monthly status records showing late payments. | Divides the applicant's total `BB_LATE_MONTHS_COUNT` by `BB_MONTHS_COUNT`. Uses combined monthly totals rather than averaging each credit's late-payment share. Applicants with no matching history receive 0 after joining. |
| BB_WORST_STATUS | bureau_balance | Highest numeric payment-status severity observed across external credits. | Converts `STATUS` to numeric values using `pd.to_numeric(errors="coerce")`, then takes the maximum per credit and applicant. `"C"` and `"X"` become missing. Applicants with no numeric statuses receive a missing value. |
| POS_LOAN_COUNT | POS_CASH_balance | Number of distinct previous POS or cash loans with monthly records. | Groups by applicant and `SK_ID_PREV`, then counts loan groups per applicant. Applicants with no matching records receive 0 after joining. |
| POS_MONTHS_COUNT | POS_CASH_balance | Total monthly records across previous POS and cash loans. | Counts monthly rows per applicant. Each monthly record contributes one count. Applicants with no matching records receive 0 after joining. |
| POS_DPD_MAX | POS_CASH_balance | Greatest number of days past due recorded for a previous POS or cash loan. | Calculates the maximum `SK_DPD` across monthly records per applicant. Missing values are ignored. Applicants with no matching records receive a missing value. |
| POS_DPD_MEAN | POS_CASH_balance | Average number of days past due across monthly records. | Calculates the mean of `SK_DPD` per applicant, ignoring missing values. Applicants with no matching records receive a missing value. |
| POS_LATE_SHARE | POS_CASH_balance | Proportion of monthly records with a positive number of days past due. | Uses `share_where` to calculate the share of records where `SK_DPD > 0`. Applicants with no matching records receive 0 after joining. |
| POS_COMPLETED_SHARE | POS_CASH_balance | Proportion of distinct previous loans marked completed at least once. | Groups monthly records by applicant and `SK_ID_PREV`, marks a loan completed if any status equals `"Completed"`, then divides completed loans by all distinct loans. Applicants with no matching records receive 0 after joining. |
| INST_COUNT | installments_payments | Number of installment-payment records associated with the applicant. | Counts installment-payment rows per applicant. Applicants with no matching records receive 0 after joining. |
| INST_LATE_SHARE | installments_payments | Proportion of installment records paid late. | Uses scheduled installment dates (`DAYS_INSTALMENT`) and payment-entry dates (`DAYS_ENTRY_PAYMENT`) to calculate the share of late records. Confirm the exact comparison and missing-date handling in `aggregate_installments`. Applicants with no matching records receive 0 after joining. |
| INST_DAYS_LATE_MAX | installments_payments | Greatest recorded delay in paying an installment, measured in days. | Calculates the maximum delay between `DAYS_ENTRY_PAYMENT` and `DAYS_INSTALMENT` per applicant, according to the installment aggregation implementation. Applicants with no matching records receive a missing value. |
| INST_UNDERPAID_SHARE | installments_payments | Proportion of installment records where the payment was less than the amount due. | Calculates the share of records where `AMT_PAYMENT < AMT_INSTALMENT`, according to the installment aggregation implementation. Applicants with no matching records receive 0 after joining. |
| INST_PAYMENT_DIFF_MEAN | installments_payments | Average difference between the amount paid and the scheduled installment amount. | Calculates the mean of `AMT_PAYMENT - AMT_INSTALMENT` per applicant. Positive values indicate payments above the scheduled amount; negative values indicate payments below it. Missing amounts are excluded. Applicants with no matching records receive a missing value. |
| CC_MONTHS_COUNT | credit_card_balance | Number of monthly credit-card records for the applicant. | Counts monthly records per applicant. Applicants with no matching records receive 0 after joining. |
| CC_BALANCE_MEAN | credit_card_balance | Average outstanding credit-card balance across monthly records. | Calculates the mean of `AMT_BALANCE` per applicant, ignoring missing values. Applicants with no matching records receive a missing value. |
| CC_UTILIZATION_MEAN | credit_card_balance | Average proportion of the available credit limit being used. | Calculates monthly credit utilization using `AMT_BALANCE` and `AMT_CREDIT_LIMIT_ACTUAL`, then averages the valid ratios per applicant. Zero-limit handling follows the implementation. Applicants with no matching records receive a missing value. |
| CC_UTILIZATION_MAX | credit_card_balance | Highest recorded proportion of the available credit limit being used. | Calculates monthly balance-to-credit-limit ratios and takes their maximum per applicant. Zero or missing limits follow the implementation's special handling. Applicants with no matching records receive a missing value. |
| CC_DRAWINGS_MEAN | credit_card_balance | Average amount drawn on the applicant's credit card per month. | Calculates the mean of the drawing-amount column used by the implementation, expected to be `AMT_DRAWINGS_CURRENT`, per applicant. Missing values are ignored. Applicants with no matching records receive a missing value. |
| CC_DPD_MAX | credit_card_balance | Greatest number of days past due recorded on the applicant's credit-card account. | Calculates the maximum `SK_DPD` per applicant, ignoring missing values. Applicants with no matching records receive a missing value. |
| CREDIT_INCOME_RATIO | application_train | Credit amount relative to the applicant's income. | Divides `AMT_CREDIT` by `AMT_INCOME_TOTAL` using the project's ratio-feature helper. A larger ratio means the credit amount is larger relative to income. Zero-denominator handling follows `safe_divide`. |
| ANNUITY_INCOME_RATIO | application_train | Scheduled loan payment relative to the applicant's income. | Divides `AMT_ANNUITY` by `AMT_INCOME_TOTAL` using `safe_divide`. A larger ratio indicates a larger scheduled payment relative to income. |
| CREDIT_GOODS_RATIO | application_train | Credit amount relative to the price of the goods being financed. | Divides `AMT_CREDIT` by `AMT_GOODS_PRICE` using `safe_divide`. A larger ratio means the credit amount is larger relative to the goods' price. |
| ANNUITY_CREDIT_RATIO | application_train | Scheduled loan payment relative to the total credit amount. | Divides `AMT_ANNUITY` by `AMT_CREDIT` using `safe_divide`. A larger ratio means the scheduled payment is larger relative to the credit amount. |

The application columns (from `application_train`) are described in `HomeCredit_columns_description.csv` and in the data card; they do not need separate rows here.
